# Cloudflare slice 1: Admin tab, token mode, native install — implementation plan

Companion to [the design](../specs/2026-11-23-cloudflare-tunnel-design.md).
Slice 1 ships the Admin tab end to end on a native systemd install with a tunnel
token. Apps, API mode and the Docker sidecar are later slices; nothing here may
pretend to support them.

## Scope

In:

- `cloudflared` detected, installed (helper button + manual fallback), started,
  stopped, restarted, versioned, logged.
- Tunnel token stored sealed, never returned.
- Admin tab: the six steps, per-step check, shared status strip, Enable switch.
- Checks: binary, token, connector connection, DNS, direct-origin advisory,
  edge path with origin nonce, Access presence.
- `CF-Connecting-IP` trusted only from the connector while the tunnel is on.
- `cloudflared` in `host-packages.txt` so the Updates page and scheduled run
  upgrade it; version-drift restart prompt.
- Docs page, CHANGELOG, version bump, rebuilt bundle.

Out (deliberately deferred to keep this reviewable):

- Apps tab, per-site publishing, ingress generation, certificate suppression
  (only meaningful once app hostnames are published — slice 2).
- API mode (tunnel creation, DNS writes).
- Docker sidecar files (`deploy/docker-compose.cloudflared.yml`). Slice 1 detects
  container mode and shows "external connector" copy plus a link to the docs
  section; the override file and its testing land with slice 4.

## Task 2 — store keys and view

Host settings (no schema change): `cloudflare_enabled`,
`cloudflare_tunnel_token` (sealed), `cloudflare_tunnel_id`,
`cloudflare_strict_origin`, and the check nonce `cloudflare_check_nonce`
(generated once on first enable, 16 random bytes hex).

New `internal/cloudflared/settings.go`:

```go
type Settings struct {
    Enabled    bool
    Token      string // plaintext, in memory only
    TunnelID   string
    StrictOrigin bool
    CheckNonce string
}
func Load(kv map[string]string, box *crypto.Box) Settings
func Apply(kv map[string]string, box *crypto.Box, in Settings) error // seals token when set
```

Rules:

- An empty token in a `PUT` keeps the stored one; explicit clearing uses
  `"token": null` semantics via a `TokenSet bool` companion field, so the UI
  cannot wipe a secret by rendering an empty field.
- `cloudflare_check_nonce` is written once and never regenerated by a PUT.

Tests (`internal/cloudflared/settings_test.go`): seal/open round trip, empty
token preserves, token never appears in `Apply` output key set twice, nonce
stability.

## Task 3 — supervisor

New `internal/cloudflared/supervisor.go`:

```go
type State string // "stopped" | "starting" | "running" | "error" | "external"
type Supervisor struct { /* bin path, version, cmd, mu, state, lastErr, ring, metricsAddr */ }

func New(log *slog.Logger, metricsAddr string) *Supervisor
func (s *Supervisor) Detect() (path, version string)
func (s *Supervisor) Start(token string) error
func (s *Supervisor) Stop()
func (s *Supervisor) Restart(token string) error
func (s *Supervisor) Snapshot() Snapshot // state, version, connections, error, log tail
```

- argv is always `cloudflared tunnel run --no-autoupdate --metrics <addr> --token <token>`.
  `--no-autoupdate` because the host package owns updates; a self-updating binary
  would fight apt and break version drift detection.
- Token goes on argv (cloudflared's own interface) — document it in the code
  comment: `ps` exposure is bounded by the service being root-owned and the
  host being the admin's; the alternative (`TUNNEL_TOKEN` env) is visible in
  `/proc/<pid>/environ` to the same users.
- Ready probe: `GET http://<metricsAddr>/ready` every 2 s while starting;
  `{"status":200}` means registered. Parse connections from `/metrics`
  (`cloudflared_tunnel_ha_connections`) when available, else report 1/0.
- Process exit → state `error`, last line of stderr kept, no auto-restart loop
  (a wrong token would spin); the page offers retry.
- Metrics address: `WAFPROXY_CLOUDFLARED_METRICS`, default `127.0.0.1:20241`.
- Boot: `cmd/wafproxy/main.go` starts it after settings load when enabled and a
  token exists, same shape as the Tailscale block; failure logs a warning.

Tests (`internal/cloudflared/supervisor_test.go`) with a fake binary (a shell
script in `t.TempDir()` that serves `/ready` and `/metrics` via `nc`-free Go
helper? — use a small generated Go program or `python3 -c`; the test harness in
this repo may not have `python3` everywhere, so ship a tiny `testdata/fakecloudflared/main.go`
built by the test with `go build`): start→running, crash→error with message,
ready timeout→starting then error, version drift reported, stop kills the child.

## Task 4 — install path

1. `deploy/cloudflared-install.sh` (fixed, no arguments):
   - require apt + root, as `crowdsec-install.sh` does,
   - fetch Cloudflare's `cloudflared` apt key, write
     `/usr/share/keyrings/cloudflare-main.gpg`, add
     `deb [signed-by=…] https://pkg.cloudflare.com/cloudflared any main`,
   - `apt-get update && apt-get install -y --no-install-recommends cloudflared`,
   - `systemctl disable --now cloudflared` (the console owns the process),
   - echo `cloudflared --version` on success.
2. `deploy/install.sh`: install the script to `$app_dir/lib/cloudflared-install`
   next to `crowdsec-install`, with the same "script missing" warning.
3. `internal/updates/protocol.go`: `HelperActionCloudflaredInstall =
   "cloudflared-install"`, `CloudflaredInstallScript = firstScript(...)`.
4. `cmd/wafproxy-updated/main.go`: dispatch with a 10-minute deadline (the
   CrowdSec 15-minute pattern), under `aptMu`.
5. `internal/api/cloudflare_install.go`: `POST /api/cloudflare/install` starts a
   goroutine that talks to the helper and stores progress in memory;
   `GET` returns `{running, ok, output, checked_at}`. Copy the shape from
   `crowdsec_install.go` including the "helper not installed" and
   "container" reasons.
6. `internal/updates/host-packages.txt` + `docs/INSTALL.md` list: add
   `cloudflared` last, with a comment that it is optional and installed by the
   console's button.

Tests: helper dispatch unit test (`cmd/wafproxy-updated` existing test style),
API test with a stub helper client for start/poll/failure, catalog test already
covers the list parser.

## Task 5 — API

New `internal/api/cloudflare.go`, routes in `internal/api/server.go` under
`s.authed`. No `rbac.go` change is needed: `permissionFor` maps an unrecognised
`/api/...` path to the `settings` area, so these routes already require
`settings.read` for GET and `settings.write` for POST/PUT. One consequence to
keep in mind: `POST /api/cloudflare/check` counts as a write permission, which is
intended — the checks restart nothing but they can trigger outbound requests to
the public hostname.

| Route | Handler |
| --- | --- |
| `GET /api/cloudflare` | `getCloudflare` |
| `PUT /api/cloudflare` | `putCloudflare` |
| `GET /api/cloudflare/install` | `getCloudflareInstall` |
| `POST /api/cloudflare/install` | `startCloudflareInstall` |
| `POST /api/cloudflare/connector` | `cloudflareConnector` (`start`/`stop`/`restart`) |
| `POST /api/cloudflare/check` | `cloudflareCheck` |

`GET` view: `enabled`, `installed`, `version`, `state`, `connections`,
`token_set`, `token_tail` (last 4 only), `tunnel_id`, `strict_origin`,
`metrics_addr`, `container`, `restart_required` (binary version changed),
`log_tail` (last 40 lines), `checks` (only if the page asked: `GET` returns the
cached result of the last run, and `POST /check` runs fresh).

`PUT`: validate (`tunnel_id` shape if present; `strict_origin` only toggles when
enabled), seal token, `SetSettings`, `AddAudit("cloudflare.update")` with key
names only, start/stop/restart the child per the enabled transition, respond
`{status:"ok"}`. Token change while running → `Restart`.

`POST /check`: body `{"hostnames": ["console.example.com"]}`; every hostname
must equal the console host (`site.console_host`) for slice 1 — Apps hostnames
arrive in slice 2. Runs the checks from the design:

1. binary via `Detect`,
2. token present,
3. connector `Snapshot().Connections > 0`,
4. DNS: `net.DefaultResolver.LookupHost` → at least one Cloudflare range
   (`104.16.0.0/13`, `172.64.0.0/13` etc., from a small table),
5. direct-origin advisory: `https://<hostname>` from the console host with a
   loopback reroute? — in slice 1, probe the console's own public address only
   if `wan_ip` is known, compare with the WAN listener; report, never fail apps,
6. edge path: `GET https://<hostname>/api/health` with
   `User-Agent: WAF-Proxy-Check/<version>` and require both a `CF-Ray` header and
   `X-WAF-Origin: <cloudflare_check_nonce>`; the GUI sets that header for
   requests with the check user agent,
7. Access: a 302 to `*.cloudflareaccess.com` means on; a 200 means off —
   reported, not failed.

Each check carries `{id, label, ok, detail, at}`; the page renders the table.

Tests (`internal/api/cloudflare_test.go`): redaction (token absent from JSON and
diagnostics), enable/disable transitions with a fake supervisor, restart on token
change and not on tunnel-id change, check endpoint rejects a hostname that is not
the console host, hostname input is never used as a raw URL, audit entries,
`host_admin` denial.

## Task 6 — client IP

`internal/clientip`:

- `Resolver` gains `cdn atomic.Bool` and `SetCDN(bool)`.
- `FromRequest`: when `cdn` is on and the peer is trusted and `CF-Connecting-IP`
  parses, return it; otherwise the existing XFF logic.
- `Resolver` stays the single instance installed via `api.SetTrustedProxies` and
  `proxy.Server.ClientIP`, so `SetCDN` flips both.

`internal/proxy/handler.go`: add `CF-Connecting-IP` and `CF-Connecting-IPv4` to
`cleanInboundHeaders` (resolution happens at handler.go:26, cleaning at :279, so
the order is already correct — add a test that pins it).

Wiring: `cmd/wafproxy/main.go` calls `trusted.SetCDN(enabled && strict_origin)`
at boot; `putCloudflare` flips it on change without a restart.

Tests: `clientip_test.go` cases (cdn on + loopback + header → value; cdn off →
peer; foreign peer with header → peer; header garbage → peer), proxy test that
the header is stripped before the upstream sees it.

## Risks

- `cloudflared`'s local API is undocumented-ish; if `/ready` or the metric name
  differs by version, fall back to "process running" plus log scanning, and say
  so in the UI rather than claiming a connection count.
- Argv token exposure (documented above); revisit if Cloudflare ships a token
  file flag.
- The origin nonce header is a behavior change on the WAN listener only for the
  check user agent; a proxy test must prove normal requests are untouched.
- Host-package updates restart nothing: version drift is detected and surfaced,
  but the restart stays a click, never automatic mid-request.
